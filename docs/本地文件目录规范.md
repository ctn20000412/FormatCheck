# 本地文件目录规范

## 1. 目录原则

每个待检测文件对应一个独立结果目录。目录名按待检测文件主文件名清洗得到，例如 `善意想`。该目录下按文件职责分成五类内容：

- `待检测文件`
- `规则规范文件`
- `规则抽取结果`
- `检测结果`
- `检测后带批注的源文件`

当前阶段不以 session 作为主要目录名。结果文件长期保留，不自动清理。

## 2. 推荐目录结构

示例：

```text
results/
  善意想/
    待检测文件/
      单奕翔：变化中的永恒——论中国民间音乐的“循环”逻辑.docx
    规则规范文件/
      中央音乐学院格式规范pdf.pdf
    规则抽取结果/
      format_rule.json
    检测结果/
      format_check_result.json
      format_check_analysis.docx
      format_check_analysis.md
    检测后带批注的源文件/
      单奕翔_格式检查批注版.docx
```

## 3. 文件分类

| 分类目录 | 内容 | 说明 |
| --- | --- | --- |
| `待检测文件` | 用户上传的 `checked_file` | 当前只支持 `.docx` |
| `规则规范文件` | 用户上传的格式规范文件 | 支持 `.pdf`、`.doc`、`.docx`、`.md` |
| `规则抽取结果` | `format_rule.json` | Agent1 输出 |
| `检测结果` | `format_check_result.json`、`format_check_analysis.docx`、可选 Markdown | Agent2 检查结果和统计分析文档 |
| `检测后带批注的源文件` | 批注版论文 `.docx` | 必须使用 Word 原生批注 |

## 4. 文件命名

| 文件 | 命名规则 |
| --- | --- |
| 规范源文件 | 保留原文件名和扩展名 |
| 待检论文 | 保留原文件名和扩展名 |
| 规则文件 | `format_rule.json` |
| 检查结果 JSON | `format_check_result.json` |
| 统计分析文档 | `format_check_analysis.docx` |
| 统计分析 Markdown | `format_check_analysis.md` |
| 批注版论文 | `{原论文主文件名}_格式检查批注版.docx` |

## 5. 结果目录名清洗规则

目录名来自待检测论文主文件名：

- 保留中文、英文和数字。
- 将冒号、破折号、引号、斜杠、空白等不适合做路径的字符替换为 `_`。
- 合并连续 `_`。
- 去掉开头和结尾的 `_`。
- 如果用户希望使用人工指定目录名，例如 `善意想`，以用户指定名称优先。
- 如果目录已存在且需要保留旧结果，追加短时间戳避免覆盖。

## 6. 下载 URL 映射

前端不直接暴露磁盘绝对路径。Java Spring Boot 将本地文件映射为下载 URL。

示例：

```json
{
  "path": "results/善意想/检测结果/format_check_analysis.docx",
  "url": "/files/善意想/检测结果/format_check_analysis.docx"
}
```

## 7. 覆盖策略

- 不覆盖原始上传文件。
- 不覆盖历史结果目录。
- 同一个结果目录内重新生成时，可以覆盖 `规则抽取结果`、`检测结果` 和 `检测后带批注的源文件` 下的派生文件。
- 如果用户再次上传同名论文并希望保留旧结果，应创建追加时间戳的新目录。
- 失败时保留已生成的中间文件，方便排查。

## 8. 清理策略

结果文件保留，不自动清理。后续如需清理，只做手动清理，不做默认删除。
