### 本地服务开发

先阅读：

- `系统架构设计.md`
- `流程设计.md`

重点实现：

- 创建以待检测文档名命名的结果目录。
- 目录内按 `待检测文件`、`规则规范文件`、`规则抽取结果`、`检测结果`、`检测后带批注的源文件` 分类保存。
- 保存上传文件。
- 调度 Agent1 和 Agent2。
- 管理中间 JSON 和输出文件。
- 将本地文件映射为前端下载链接。

### Agent 开发

先阅读：

- `Agent与Prompt说明.md`
- `数据结构说明.md`
- `测试用例.md`

重点实现：

- Agent1 调用 `extract-format-rules` skill。
- Agent2 调用 `check-paper-format` skill。
- 校验 LLM JSON 输出。
- 处理非法 JSON、空规则、批注定位失败等异常。

## 已确认实现约束

- 前端使用 Vue。
- 接口层使用 Java Spring Boot。
- LLM 交互和 Agent 执行使用 Python。
- Java 使用 `ProcessBuilder` 启动 Python 脚本。
- 模型厂商包括 `deepseek`、`chatgpt`、`claudecode`、`kimi`、`glm`。
- API Key 和 Base URL 只在 Python 中配置。
- 规范文件支持 `.pdf`、`.doc`、`.docx`、`.md`。
- 待检测论文当前只支持 `.docx`。
- 格式规则优先由程序读取 Word 属性检查。
- 错别字和语法错误由 LLM 判断。
- 分析文档输出 `.docx`。
- 批注版论文必须使用 Word 原生批注。
- 结果目录按待检测文档名创建，长期保留，不自动清理。
