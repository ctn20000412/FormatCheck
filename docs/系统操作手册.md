# 系统操作手册

## 1. 适用范围

本文档用于本项目当前单机版系统的本地启动、页面操作、文件下载和结果查看。

当前系统由三部分组成：

- 前端：Vue + Vite，提供单页操作台。
- 后端：Java Spring Boot，提供接口、文件保存、下载链接，并通过 HTTP 调用 Python Agent。
- Agent：Python 常驻本地 HTTP 服务，独立运行并负责调用 LLM。

当前版本说明：

- 规范文件支持 `.pdf`、`.doc`、`.docx`、`.md`。
- 待检测论文当前仅支持 `.docx`。
- 前端不提供 API Key、Base URL、temperature、max_tokens 等配置入口。
- 前端不允许用户编辑 `format_rule.json` 后继续检测。
- 前端不预览原始上传文件，只负责上传、展示统计和下载结果。
- Python Agent 当前已支持真实 OpenAI-compatible LLM API 调用。以 `deepseek / deepseek-v4-flash` 为例，只要本地配置了 API Key，检测时会真实调用 DeepSeek API。
- 如果某个模型没有配置 API Key，Python 会回退到占位输出，用于本地流程验证。
- 当前已具备基础 `.docx` 文本读取和 LLM JSON 结果写入；完整 Word 样式解析、原生批注写入和完整规则引擎仍需后续继续增强。

## 2. 运行前准备

确认本机具备以下环境：

- Java 17 或以上。
- Maven，本项目当前使用：`C:\Users\ning\apache-maven-3.9.6\bin\mvn.cmd`。
- Python，用于启动独立运行的 Agent 服务。
- Node.js，前端依赖 Vue/Vite。
- npm。若 PowerShell 提示 `npm.ps1` 执行策略错误，使用 `npm.cmd`。

建议先执行：

```powershell
java -version
python --version
node --version
npm.cmd --version
```

## 3. 启动 Python Agent 服务

Python Agent 必须单独启动，并在整个检测过程中保持运行。Java 后端不会再通过 `ProcessBuilder` 临时启动 Python，也不会在接口调用结束后关闭 Python 进程。

启动前建议先确认模型配置和 DeepSeek Key。

```powershell
Set-Location E:\code\formatCheck\agent-service
python -m app.llm_config show deepseek
```

如果输出中：

```json
"api_key_configured": true
```

说明 `deepseek / deepseek-v4-flash` 会走真实 DeepSeek API。

如果为 `false`，先配置本地 Key：

```powershell
Set-Location E:\code\formatCheck\agent-service
python -m app.llm_config set-api-key deepseek 你的DeepSeekKey
python -m app.llm_config show deepseek
```

启动常驻 Python Agent：

```powershell
Set-Location E:\code\formatCheck\agent-service
python -m app.main --serve --host 127.0.0.1 --port 8001
```

启动成功后，终端会显示：

```text
[agent-service] Python Agent 已启动：http://127.0.0.1:8001
```

LLM 的流式日志会实时打印在这个 Python 终端中，包括：

```text
[agent1_extract_format_rules] 提示词 ...
[agent1_extract_format_rules] 思考片段：...
[agent1_extract_format_rules] 回答片段：...
[agent2_check_paper_format] 思考片段：...
[agent2_check_paper_format] 回答片段：...
```

说明：能打印出的“思考片段”仅限模型 API 返回的 `reasoning_content` 或同类字段；如果某个模型不返回该字段，系统不会伪造思考内容，只会打印回复片段。

## 4. 启动后端服务

打开 PowerShell，进入后端目录：

```powershell
Set-Location E:\code\formatCheck\backend
```

启动 Spring Boot：

```powershell
& 'C:\Users\ning\apache-maven-3.9.6\bin\mvn.cmd' '-Dmaven.repo.local=E:\code\formatCheck\.m2\repository' spring-boot:run
```

后端默认端口为：

```text
http://127.0.0.1:8080
```

后端关键配置文件：

```text
E:\code\formatCheck\backend\src\main\resources\application.yml
```

当前配置含义：

| 配置项 | 当前值 | 说明 |
| --- | --- | --- |
| `server.port` | `8080` | 后端接口端口 |
| `format-check.storage-root` | `../results` | 结果文件保存目录 |
| `format-check.model-config` | `../agent-service/config/llm_providers.json` | Java 读取模型厂商和型号列表的配置文件 |
| `format-check.agent-base-url` | `http://127.0.0.1:8001` | 常驻 Python Agent 服务地址 |
| `format-check.agent-timeout-seconds` | `300` | Java 等待 Python Agent 返回的超时时间 |

### 4.1 配置模型厂商、API 和 URL

模型厂商、模型型号、API 协议、Base URL 和 API Key 环境变量统一维护在：

```text
E:\code\formatCheck\agent-service\config\llm_providers.json
```

当前内置厂商对照：

| 厂商 | API 协议 | 默认 Base URL | API Key 环境变量 |
| --- | --- | --- | --- |
| `deepseek` | OpenAI compatible | `https://api.deepseek.com` | `DEEPSEEK_API_KEY` |
| `chatgpt` | OpenAI | `https://api.openai.com/v1` | `OPENAI_API_KEY` |
| `claudecode` | Anthropic | `https://api.anthropic.com/v1` | `ANTHROPIC_API_KEY` |
| `kimi` | OpenAI compatible | `https://api.moonshot.ai/v1` | `MOONSHOT_API_KEY` |
| `glm` | OpenAI compatible | `https://api.z.ai/api/paas/v4` | `ZAI_API_KEY` |

本地 API Key 和自定义 URL 不写入主配置文件，使用忽略提交的本地覆盖文件：

```text
E:\code\formatCheck\agent-service\config\llm_providers.local.json
```

推荐通过 Python 设置命令生成和修改本地覆盖文件：

```powershell
Set-Location E:\code\formatCheck\agent-service
python -m app.llm_config list
python -m app.llm_config show deepseek
python -m app.llm_config set-url deepseek https://api.deepseek.com
python -m app.llm_config set-api-key deepseek sk-xxxx
python -m app.llm_config set-api-key-env deepseek DEEPSEEK_API_KEY
```

说明：

- `/api/models` 由 Java 读取 `llm_providers.json` 后返回给前端。
- 任务提交时，Java 使用同一份配置校验 `provider` 和 `model`。
- Python Agent 执行任务时会读取主配置和本地覆盖配置，最终解析出 Base URL、API Key 环境变量和实际 Key。
- 前端不会展示或保存 API Key。
- 主配置文件 `llm_providers.json` 不保存真实密钥，只保存环境变量名和默认 URL。
- 本地密钥保存在 `llm_providers.local.json`，该文件已被忽略提交。

### 4.2 验证 DeepSeek 真实 API

执行：

```powershell
Set-Location E:\code\formatCheck\agent-service
python -m unittest tests.test_live_deepseek_api
```

结果为：

```text
OK
```

表示当前本机可以真实访问 DeepSeek API。

如果提示 socket 权限或网络权限错误，说明当前运行环境不允许联网；这不是代码逻辑错误，需要换到允许联网的终端运行，或给当前执行环境放开网络访问。


```powershell

```

```powershell

```

前端默认地址：



## 6. 页面操作流程

### 6.1 打开系统

在浏览器中打开：

```text
http://127.0.0.1:5173
```

页面加载后会显示“论文格式检查工作台”。

### 6.2 选择模型

在“检测任务”区域选择：

- 模型厂商：`DeepSeek`、`ChatGPT`、`Claude Code`、`Kimi`、`GLM`。
- 模型型号：由后端 `/api/models` 返回。

如果后端未连接，前端会使用内置默认模型列表显示页面，但提交检测仍需要后端运行。

### 5.3 上传格式规范文件

点击“上传格式规范文件”，选择规范准则文件。

允许格式：

```text
.pdf, .doc, .docx, .md
```

### 5.4 上传待检测论文

点击“上传待检测论文”，选择待检测论文。

当前仅允许：

```text
.docx
```

如果上传非 `.docx` 文件，前端会直接阻止提交。

### 5.5 开始检测

点击“开始检测”。

前端会向后端提交：

- `provider`
- `model`
- `standardFile`
- `checkedFile`

后端收到后会：

1. 校验模型厂商和文件格式。
2. 按待检测论文名称创建结果目录。
3. 保存上传的规范文件和待检测论文。
4. 写入 `agent_request.json`。
5. 通过 `ProcessBuilder` 临时启动 Python Agent。
6. Python 读取模型配置；如果 API Key 已配置，则调用真实 LLM API。
7. Python 生成规则 JSON、检测结果 JSON、统计分析文档和批注版论文副本。
8. Java 读取 Python 返回结果。
9. 返回统计数据和下载链接给前端。

### 5.6 查看结果

检测完成后，页面会展示：

- 错误总数。
- 已检查规则数。
- 需人工确认数。
- 按类别统计。
- 按严重程度统计。
- 错误明细表。

如果模型 API Key 已配置，错误统计和错误明细来自真实 LLM 返回的 JSON。

如果未配置 API Key，系统会返回占位统计，错误总数通常为 0。

### 5.7 下载结果文件

检测完成后，页面提供三个下载入口：

| 下载入口 | 文件 |
| --- | --- |
| 格式规范 JSON | `format_rule.json` |
| 错误统计分析 | `format_check_analysis.docx` |
| 批注版论文 | `<论文名>_格式检查批注版.docx` |

点击下载链接后，浏览器会通过后端 `/api/files/**` 下载本地结果文件。

## 6. 本地结果目录

结果默认保存在：

```text
E:\code\formatCheck\results
```

每次检测按待检测文件名创建一个目录，例如论文名为 `paper.docx` 时：

```text
E:\code\formatCheck\results\paper
```

目录结构如下：

```text
results/
  <待检测文件名>/
    待检测文件/
      <原始待检测论文>.docx
    规则规范文件/
      <原始规范文件>.pdf
    规则抽取结果/
      format_rule.json
    检测结果/
      agent_request.json
      format_check_result.json
      format_check_analysis.docx
      format_check_analysis.md
    检测后带批注的源文件/
      <论文名>_格式检查批注版.docx
```

系统当前不会自动清理结果目录。

## 8. 常见问题

### 8.1 前端能打开，但提交失败

优先检查后端是否启动。

访问：

```text
http://127.0.0.1:8080/api/models
```

如果无法访问，先启动后端服务。

如果 `/api/models` 正常，但提交检测返回：

```json
{
  "success": false,
  "message": "Python 执行失败: ..."
}
```

优先检查：

```powershell
Set-Location E:\code\formatCheck\agent-service
python -m app.llm_config show deepseek
python -m unittest tests.test_live_deepseek_api
```

同时确认后端已经在修改代码后重新启动。

### 8.2 PowerShell 提示无法加载 `npm.ps1`

使用：

```powershell
npm.cmd install
npm.cmd run dev
```

不要直接使用 `npm install`。

### 8.3 提示待检测论文格式不支持

当前版本待检测论文只支持 `.docx`。请将论文保存为 Word `.docx` 后重新上传。

### 8.4 规范文件上传失败

确认规范文件后缀是否为：

```text
.pdf, .doc, .docx, .md
```

### 8.5 端口被占用

检查 8080：

```powershell
Get-NetTCPConnection -LocalPort 8080
```

检查 5173：

```powershell
Get-NetTCPConnection -LocalPort 5173
```

如需停止某个进程：

```powershell
Stop-Process -Id <PID>
```

### 8.6 下载链接打不开

检查结果文件是否存在于：

```text
E:\code\formatCheck\results\<待检测文件名>
```

同时确认后端服务仍在运行，因为下载链接由后端 `/api/files/**` 提供。

## 9. 停止服务

如果前后端是在 PowerShell 前台启动的，回到对应窗口按：

```text
Ctrl + C
```

如果服务是后台进程，先查询端口或进程 ID，再执行：

```powershell
Stop-Process -Id <PID>
```

## 10. 演示建议流程

1. 配置 DeepSeek Key：`python -m app.llm_config set-api-key deepseek 你的DeepSeekKey`。
2. 验证 Key：`python -m app.llm_config show deepseek`，确认 `api_key_configured` 为 `true`。
3. 验证真实 API：`python -m unittest tests.test_live_deepseek_api`。
4. 启动后端。
5. 启动前端。
6. 打开 `http://127.0.0.1:5173`。
7. 选择 `DeepSeek` 和 `deepseek-v4-flash`。
8. 上传规范文件。
9. 上传 `.docx` 论文。
10. 点击“开始检测”。
11. 查看统计数据和错误明细表。
12. 下载 `format_rule.json`、错误统计分析文档和批注版论文。
13. 到 `results/<待检测文件名>/` 查看本地保存的所有文件。
